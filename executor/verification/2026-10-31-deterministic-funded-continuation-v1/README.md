# Conditional v14 settlement and exact-proof continuation

Read [the full scope, state assumptions, failures and release gates](../../../docs/security/DETERMINISTIC_FUNDED_CONTINUATION_20261031.md).
This contains 16 unique native-verified **synthetic** complete UPSs: one grant
from the failed first run, reused exactly in the corrected run, and 15 new UPSs.
Three simulated fills and two refunds occur per normal market path. Timeout and
abort are alternative histories with common prefixes, not extra real trades.

Initial activation/pool/inventory and ordinary actor actions are VM prerequisites.
The starting zero-cap/nonzero-nonce fixture is not proven reachable through the
fresh v14 bootstrap. This pack and the earlier bootstrap pack are independent
cohorts, not one empty-vault-to-user-arrival chain. No deployment, send, ordinary
wallet signature, network receipt, finality or real UI payment is accepted here.

`index.json` contains SHA256 values for 247 original/public/gzip members.
`PUBLISHED-AUDIT.json` is a publication checksum/field audit, not a ZK verifier.
`SUMMARY.json` describes the accepted and still-conditional boundaries. Paths
are projected to placeholders. No binary, wallet, raw signing/CFC witness,
private key or mnemonic is published. Public proofs, Merkle openings and the
explicit SDK public-session projection are included. Constant synthetic test-key
code is not a live wallet export.

  source pages, state edges, 4+1 members, actual compiled fill/refund method names,
  lifetime key/cap/fees and ordinary VM claim records reconcile. This is not
  cryptographic verification.
- `public/ACTIVE-*.json`, `CLOSED-*.json`, `rss-*.jsonl`: sealed executables,
  ownership, exact lifecycle intervals and all sampled RSS. RSS is not physical
  peak; the sample series cannot prove absence of a sustained-service leak.
- `application-v1/v2/*`: original and corrected full-proof driver snapshots.
- `application-v3/v4/*`: additional checkpoint/history/persistence guards;
  v3 retains the Felt/u64 compiler error and v4 compiles and passes the replay

## Reproduction

Materialize SDK `c92880c8b6e2c8d392f19368bc8801a2584fd427` using
[the frozen dependency guide](../../../batching/dependencies/README.md).
Use the previous pack's exact Native/FT/NFT and AMM/Curve fixtures; verify every
hash in `FIXTURE-REFERENCE-v1.json` and the linked build manifest/index first.
These IDs and checkpoints are synthetic and must never be broadcast on a live
chain. Do not infer a deployable resource bundle from a matching ABI.

Prepare an application snapshot outside the repository/frozen sources:

```sh
python3 batching/dependencies/prepare_mainnet_beta_application.py --source "$FROZEN_SOURCE" --out "$FRESH_APPLICATION" --test-only
```

Set `PSY_NETWORK=testnet`,
`PSY_MARKET_TESTNET_PROFILE=mainnet-beta-20261027-v1`, `RAYON_NUM_THREADS=2`
and `BATCH_BUILD` to the exact prior fixture directory. Set `FUNDED_STREAM_OUT`
to a fresh output directory. Declare a sole proof owner and finite compute
bounds before running this intentionally ignored expensive test:

```sh
cargo +nightly-2025-09-20 test --offline --locked --release --manifest-path "$FRESH_APPLICATION/Cargo.toml" --test batch_lifecycle deterministic_funded_stream_complete_ups_continuation -- --ignored --test-threads=1 --nocapture
```

A clean run creates 16 complete UPSs. For the owned recorded failure,
`FUNDED_STREAM_REUSE_GRANTS` points to the original `full-ups-v1` directory;
the exact AMM grant is reverified/replayed and only 15 new UPSs are made. Do not
point this synthetic test at arbitrary external wallet material. Seal/hash the
test executable and retain original input/output versions as the harnesses do.

The separate saved-proof control needs the original AMM funding-grant directory
in `FUNDED_REPLAY_GUARD_INPUT` and a fresh `FUNDED_REPLAY_GUARD_OUT`:

```sh
cargo +nightly-2025-09-20 test --offline --locked --release --manifest-path "$FRESH_APPLICATION/Cargo.toml" --test batch_lifecycle deterministic_saved_grant_reuse_rejects_changed_context -- --ignored --test-threads=1 --nocapture
```

The final controls compile on application-v4 and generate no new full proof.
To inspect existing public projections, set `FUNDED_STREAM_UPS` to decompressed
`full-ups-v2`, then run:

```sh
node --test batching/checkpoint-stream/audit-funded-stream-evidence.test.mjs
node batching/checkpoint-stream/audit-funded-stream-evidence.mjs "$FUNDED_STREAM_UPS"
```

Fixture-dependent tests skip without their environment variable; the archived
final invocation supplies it and has five passes/no skips. For actual proof
checking, compile `verify_saved_ups` from the same frozen cohort and invoke it
with `PUBLIC_REQUEST FRESH_REPORT`; the sealed verifier digest used here is
`df869eef7806ad6f793d209e9b31f6a6a3a9477a7a6d4a1b316cea8504772762`.
Its fixed Endcap/public-input checks do not replace the spending-key/session
binding checks at original generation or formal wallet approval.

Formal v14 signing/Executor integration, reachable lifecycle linkage, budget and
service/refund liveness, unused treasury exit, Book/NFT bootstrap and actual
ordinary-wallet/UI settlement remain release gates. No production, speedup,
chain TPS, global fairness, random-finality or cross-machine claim follows.
