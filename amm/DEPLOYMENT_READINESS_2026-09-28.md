## Real-asset test

Alice (`135168`) opened a PSY-input swap order and paid the pool `1,001,100,000` PSY base units. The intended input is `1,000,000` units and the rest is fee escrow. Checkpoint `74541` confirmed transaction `127dc32075c2a872c3da49df5bdc9913c662d7ccae8e74bee4b34cb5af9242ea`. The payment was initially unclaimed and was later used to test the refund path below.

The first refund guard proof failed locally, so the contract guard was updated with an unchanged state layout. A subsequent remote proof failed, apparently because the proving service continued to use the old method circuit after that update. A fresh local-prover attempt also failed with a conflicting witness wire. A second local-prover attempt on 2026-09-29 reproduced the failure at `refund_unclaimed` call index `0`: `Partition containing Wire(Wire { row: 554, column: 51 }) was set twice with different values: 0 != 16463394126558395459`. A proposed removal of the order checks was rejected by automatic approval review as a security weakening; that change was restored and never submitted. A separate read-only staging diagnostic contract `61` confirmed that one or two payer order reads, a payer Outbox read, and their combination can prove; the combination of payer Outbox and pool claimed slot fails with the same wire-conflict class. The subsequent cursor update preserves the order and exact-payment checks and replaces claimed-slot reads with pool-owned cumulative settlement cursors. A subsequent live refund proof succeeded; its on-chain result is recorded below.
