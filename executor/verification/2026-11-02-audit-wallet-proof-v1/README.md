# Audit complete ordinary-wallet verification

Two fresh complete ordinary proofs pass. The initialized account submits AMM order/funding/fee calls with a full dual-Felt amount; the zero-stored-leaf case claims pending Native and pays its fee under the separately pinned registration-start proof. Both use the current captured Native code/layout/function identity. Both validate the complete CFC/UPS chain, signature/session/sig_hash, calls/order/amounts/caller context, code/layout/function membership, fees, nonce, endpoints and exact request identity. Fifteen negative mutations reject recipient, asset, high limb, call order, nonce, network, starting leaf, expiry, fee cap, CFC/UPS/signature proof, session root, delta root and code root.

The initialized process takes 161.500 seconds with sampled family RSS peak 2,608,336 KiB; its cold circuit build is 115.502 seconds. The first-session process takes the duration and RSS recorded in public/first-COHORT-v1.json.gz. These are full-lifecycle synthetic proof correctness samples, not a matched performance comparison, RPC confirmation or browser acceptance. One process per case is used. Each ordinary proof is stored as a flat request.json; the original wrapper's completeRequestFiles counter counted only child directories and incorrectly reports zero. There is exactly one proof per case, confirmed by the retained request/bundle/report. No originals are rewritten.

The historical wallet pool fixture tried a retired batch-settlement entry and rejected before generating a proof. The corrected fixture uses actual token transfer/claim bytecode to back explicitly declared synthetic reserves; it does not pretend to prove historical liquidity admission. The short compile-helper qualification error and wrapper-record collisions are retained. No safety checks were deleted and no payment was retried.

A bounded read of the configured faucet first failed local Python certificate verification. Independent OpenSSL validation succeeded with the trusted CA bundle; an explicit second read using verified OpenSSL curl succeeded, reporting an enabled 1,000 test-PSY faucet and no Turnstile requirement. No faucet claim, account creation, registration, payment or repeat old request occurs. The service was not declared TLS-broken on the basis of the Python transport failure.

All original proofs/public bundles, verifier-only resources, reports and failures are compressed immutably with raw/stored SHA256 values in INDEX.json. Ephemeral signing keys are not persisted. The synthetic verifier pack must not be installed as live resources. Actual WASM build/reverification and new-instance browser/native network acceptance follow separately.
