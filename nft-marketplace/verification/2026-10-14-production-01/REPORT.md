## HTTPS 与常驻执行

直接 Rust HTTPS 读取失败的根因是应用构建的 reqwest 0.12 未启用 TLS。应用 Cargo.toml 显式启用 native-tls，证书及域名验证保持开启。修复后官方 HTTPS 的认证 CFC 验证通过，竞争成交及退款的完整 UPS 也直接通过官方 HTTPS 执行。旧版传输、二进制和失败日志保留；没有把临时转发器作为常驻服务依赖。

AMM / Orderbook / Curve 的 U124 服务升级到冻结 app-v3 和 HTTPS 驱动，三个 fingerprint、公钥、合约 ID、根和原持久 runtime 均保持。原 app/app-v2、配置、二进制和安装 plist 留作恢复。首次 launchd bootstrap 在旧任务退出期间返回 5，稍后同一已准备配置启动成功。较早的 legacy 服务未修改。

另行安装 NFT 登录服务 `xyz.psy.executor.nft.staging`，使用冻结源、官方 HTTPS 和已对账的持久日志副本。原测试日志保留，复制前检查无未决提交和锁。启动扫描无待处理动作，随后心跳及 checkpoint 持续推进。macOS 登录服务依赖唤醒、网络和用户会话，不构成生产可用性保证。运维方式见 [NFT 服务说明](../../../executor/operations/staging-nft-2026-10-14/OPERATIONS.md)。Linux systemd 模板已提供，但未在生产服务器上安装或验收。

新执行器对全部 U124/NFT profile 核对 fingerprint 与由公开 SD-key 派生的公钥哈希。旧的只支持 fingerprint 命令的二进制不能用于这份新源版本。

## 安全审查边界

当前 SD-key introspection 绑定 ID、method ID、参数及完整调用栈；应用检查 code/layout roots。**不能把应用根检查描述成 fingerprint 在链上冻结了代码。** 部署者的更新权限、发行权限和代码根认证方式仍属于独立审查范围。没有开启 SDK 明确禁止的未认证状态读取功能，没有对现网提交未经验证的 layout 更新。

这份报告确认可重复的工程测试及测试网结果，不是第三方安全审计报告或生产运行认证。
