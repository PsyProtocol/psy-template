## Open issues and acceptance

- **P0 unilateral revocation unavailable.** On contract 48 Bob's proof anchors
  34798, Alice's request confirms 34807, Bob spends 40 at 34815. Cooperative close
  refunds correctly, but refusal to close locks the remainder. Do not advertise
  ERC-20 approve/transferFrom. Protocol needs a proof-bound authorization read set
  checked against current remote state in deterministic commit order. Acceptance:
  request first rejects old/fresh spends; spend first refunds only remainder;
  races cannot duplicate refunds. Node work belongs to its team and was not
  authorized in this handoff.
- **P1 private-token deployment path.** Legacy .psy and builtin token already have
  private_transfer/claim without Node changes, but v3 .psy.rs then lacked them.
  psyup build emits/checks legacy artifacts; old dargo arrays are incompatible with
  layout-aware deployment, and an attempted wrapper gave Invalid target index.
  Require compatible full compilation/deployment, real proofs, duplicate rejection,
  two-user acceptance and conservation, not a debit-only private deposit. Migration
  is separate.
- **P1 NFT liveness/capacity.** Full/offline/nonclaiming recipients can occupy FIFO
  indefinitely. Limits: 128 holdings, four unACKed transfers/direction, 24-bit users.
  Specify product rules, test full/unregistered/offline recipients and races. Any
  cancellation/refund must prove it cannot duplicate historical NFTs. Larger
  capacity needs new layout/migration.
- **P1 NFT operator authorization absent.** Only owner sends/recipient claims.
  Marketplace escrow or signed-intent swap authorization/revocation needs design.
- **P1 toolchains differ.** Legacy/v3 deployment differ. Public CLI 0.1.1 failed
  canonical layout fingerprint; Node-matched CLI deployed PSY-20. IDE v3 deployment
  was unverified; direct psyup deploy bypasses issuer wallet preflight. Pin toolchain,
  artifact/protocol, validate checked CLI/IDE/user identity/ABI, and mark unguarded
  routes explicitly.
- **P2 adversarial/release closure.** Historical/concurrent NFT cases, stale local
  caller rejection, four-Felt wallet/indexer integration, hosted CI, independent
  audit and upgrade/migration drills remained open.

## Minimal revocation reproduction

1. Alice request confirmed **34749**; Bob subsequently creates a spend. Contract
   rejects `channel is not active`; Bob spends zero and Alice recovers 100.
   [Rejection](tests/live/evidence/2026-09-23/token-delegation-v3-active-guard-negative.json).
2. Bob creates proof at **34798**; Alice requests at **34807**; unchanged proof
   confirms **34815**, spending 40. Bob then closes; Alice recovers 60.
   [Original](tests/live/evidence/2026-09-23/token-delegation-v3-active-guard-historical-spend.json).

ACTIVE checks protect fresh reads only. Zero allocation or owner-local nullifiers
do not invalidate historical remote proofs. Remote reads bind anchor checkpoint,
not latest remote leaf at confirmation. Cumulative transfer/claim counters avoided
double claims in tested orderings; that does not establish safe unilateral delegation.

## Handoff order

1. Publish the accurate experimental cooperative escrow-channel scope; keep
   standard unilateral authorization blocked. Sixteen concurrent slots are required.
2. Protocol team designs current-remote-read validation/public inputs/realm ordering,
   starting with the historical-proof negative case. Do not modify Node here.
3. Contract team then defines request/zeroing/spend/refund ordering and preserves
   multiple concurrent authorizations.
4. Product/integration resolves NFT liveness/capacity/market delegation, wallet,
   indexer, ABI versioning and migration.
5. Freeze tooling, complete chain adversarial cases/clean CI/independent audit,
   then decide mainnet readiness.
