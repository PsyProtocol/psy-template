# PSY-20 template verification status — 2026-09-23

> Historical baseline from before the PSY-20 v3 port and cooperative delegation work later on 2026-09-23. Its gate, method coverage, and release decision are superseded by [`token/README.md`](../../token/README.md), [`PRODUCTION_READINESS.md`](../../PRODUCTION_READINESS.md), and [contract 46 staging evidence](evidence/2026-09-23/token-delegation-v3.json).

This report concerns `token/src/main.psy` in this repository. Staging contract 0 is the chain's built-in token and is **not** this template.

## Test result

- `cd token && npm test`: passed. The native `dargo` fixture is generated from the current contract source, with an explicit test-only deployer check. One positive lifecycle checks metadata, authority self-affirmation, mint, burn, transfer, both batch methods (including repeated recipients), two private note insertions, and renunciation. Nine isolated negative cases cover delegation creation gate, unauthorized authority change, mint and metadata after renunciation, recipient bounds, inactive-channel revocation, noncanonical private proof index, and out-of-range callers for both batch methods.
- `cd token && npm run build`: passed; the generated legacy ABI lists all 15 methods.
- Repository root `npm test`: passed (2 native suites, 7 E2E suites) after selecting the installed 0.1.1 CLI for NFT v3 compilation. The PSY-20 lifecycle and delegation E2E suites are JavaScript models; they do not execute the token contract on the network or verify ZK proofs.
- The installed staging-compatible 0.1.1 CLI rejects `token/src/main.psy` during compilation: `Unexpected token LBracket at offset 1`. The legacy `psyup build` emits the older artifact shape that the staging coordinator rejected for the NFT template. The PSY-20 template has not been deployed on staging, so no real multi-user transaction can yet be attributed to it.

## Findings and release decision

1. **Fixed:** both batch transfer methods lacked the sender user-ID bound present in `transfer`. An out-of-range sender could debit their balance into an Outbox whose recipient cannot claim from that sender. Both methods now reject such callers; native negative cases exercise the guard.
2. **Hardened while gated:** delegation channel opening now checks owner and spender IDs before it can lock funds if the gate is ever lifted. Finalization validates spender ID. `private_claim` rejects proof indices with high bits that its 16-level path would ignore.
3. **Open blocker:** port the required PSY-20 methods to the staging `.psy.rs` compiler and deploy the exact release candidate. The new compiler's API for the existing private proof checks also needs a protocol-level mapping before `private_claim` can be carried over faithfully.
4. **Open blocker:** prove and exercise multi-user claim, private proof generation and redemption, and any delegation settlement on the target network. Staging has accepted historical remote state proofs; the delegation gate must stay enabled until a safe protocol rule exists.
5. **Feature gaps:** the two mining reward storage fields have no callable claim/reward method; `set_mint_authority` deliberately only reaffirms the issuer; there is no usable delegated spend/allowance path in the default build. Document or implement these according to the intended PSY-20 interface before claiming standard or production completeness.

**Current decision:** the local legacy contract's tested paths pass, but this PSY-20 template is not ready for staging deployment or production value.
